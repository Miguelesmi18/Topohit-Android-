1La idea en un minuto

Topohit es un juego de golpear topos para niños de 5 años. Lo forman cuatro piezas que se pasan datos entre sí:

🧠 La frase para recordar La tablet y el escritorio nunca tocan la base de datos. Le piden todo a la API, y la API es la única que habla con SQL Server. La tablet lo hace por wifi; por eso no necesita cable.

¿Por qué se hace así?

  • Los mismos datos en las dos apps: la partida que juega un niño en la tablet la ve la educadora en el escritorio un momento después.
  • Lo pide el reto: «implementar la API JSON para subir y descargar datos de SQL Server».
  • Seguridad: la contraseña de la base de datos solo la conoce la API, y las apps solo pueden hacer lo que la API les deja según su rol.
  • Orden: si cambia la base de datos, se toca la API y las apps siguen igual.
💡 Un ejemplo de la vida real Es como un restaurante: la tablet y el escritorio son los clientes, la API es el camarero y la base de datos es la cocina. Los clientes no entran en la cocina; le piden las cosas al camarero (una petición) y él les trae el plato (una respuesta en JSON).

3El viaje de una partida

Sigamos a Marc desde que entra en el juego hasta que su educadora ve la partida en el escritorio:

  1. Entra. Marc escribe su usuario y su contraseña. La tablet cifra la contraseña con bcrypt (Cifrado.kt) y envía POST api/auth/login con el usuario y el hash, nunca la contraseña.
  2. La API le da un «pase». Compara el hash con el de la base de datos. Si coincide, devuelve un token JWT que vale 8 horas, más su id, rol, temática y avatar. La tablet lo guarda en sesion.txt (GestorSesion.kt).
  3. Elige dificultad. La tablet pide GET api/sesiones/dificultades enseñando el token. La API contesta qué dificultades tiene abiertas y cuáles tienen candado, y por qué.
  4. Juega. Todo el juego pasa dentro de la tablet (PartidaActivity.kt): salen topos, los golpea, se cuentan los aciertos, los fallos, los topos que se escapan, el tiempo de reacción y las ayudas. Aquí no hace falta la red.
  5. Guarda la partida. Al acabar, la pantalla de Resultado envía POST api/sesiones con un JSON con todos los números. La API comprueba el token y que la dificultad esté abierta, y la guarda en la tabla SESION.
  6. Ranking y desbloqueo. La tablet vuelve a pedir el récord y las dificultades. Si ha llegado a 500 puntos en Fácil, sale «¡Has desbloqueado Normal!».
  7. La educadora lo ve. En el escritorio, la educadora entra con su usuario y la app pide, por ejemplo, GET api/jugadores/{id}/sesiones: la partida de Marc ya está ahí.

4Cómo hablan sin cable

La tablet y el PC están en la misma red wifi. Cada aparato de esa red tiene una dirección IP (por ejemplo 192.168.1.20), y cada programa que escucha dentro de un aparato tiene un puerto. La API escucha en el 5110. Así que, para llamar a la API, la tablet usa http://IP-del-PC:5110/api/….

Las tres direcciones que hay que conocer

Desde…Dirección de la APIPor qué
El escritorio (mismo PC)http://localhost:5110/localhost significa «este mismo ordenador»
El emulador de Androidhttp://10.0.2.2:5110/api/El emulador es un «móvil dentro del PC»; para él, 10.0.2.2 es el PC
La tablet de verdadhttp://192.168.x.x:5110/api/Hay que poner la IP real del PC en la wifi
⚠️ Lo más importante para la Tab A La dirección está en SharedData.kt (PROJECT_ROOT). Ahora pone 10.0.2.2, que solo sirve para el emulador. Para la tablet de verdad hay que poner la IP del PC (en Windows: ipconfig → «Dirección IPv4») y volver a instalar la app. Si cambias de wifi, la IP puede cambiar.

5Seguridad: contraseñas, token y roles

🔒 1. La contraseña nunca viaja ni se guarda «en claro»

La tablet y el escritorio la pasan por bcrypt antes de enviarla. bcrypt convierte marc1234 en algo como $2a$10$3s5iPBl…, y no se puede dar la vuelta. La base de datos guarda ese hash, así que aunque alguien vea la tabla, no ve las contraseñas.

  • Tablet: Cifrado.kt con la librería jBCrypt. Escritorio: BCrypt.Net-Next.
  • Usan la misma sal fija para que el mismo usuario dé el mismo hash en las dos apps y la API solo tenga que comparar.

🎫 2. El token JWT: el «pase» de cada petición

Tras el login, la API firma un token JWT con su clave secreta (Jwt:Clave de appsettings.json). Dentro va quién eres y tu rol, y caduca a las 8 horas. En cada petición, la app lo envía en la cabecera Authorization: Bearer …. Si falta o ha caducado, la API contesta 401 y la app vuelve al login.

  • API: Auth/Tokens.cs, Auth/JwtConfig.cs y Program.cs, con la librería Microsoft.AspNetCore.Authentication.JwtBearer.

👥 3. Los roles deciden qué puedes hacer

En los controladores de la API, cada llamada lleva una etiqueta, por ejemplo [Authorize(Roles = Roles.ADMIN)]. Un niño con su token de jugador no puede pedir api/usuarios: la API le contesta 403.

🗝️ 4. La contraseña de la base de datos

Solo la conoce la API (appsettings.json, cadena ConnectionStrings:Topohit). Las apps no la tienen. Por decisión del equipo, este archivo se sube a git porque es un proyecto de clase en un entorno cerrado.

🧠 Resumen de seguridad en 3 líneas bcrypt protege las contraseñas · el token JWT dice quién eres en cada petición · los roles dicen qué puedes hacer.

8Métricas con Python

El reto «Mètriques dels jocs» pide analizar por qué los niños dejan de jugar, con Python (pandas, matplotlib y un modelo de predicción), y enseñar el resultado en una vista «Mètriques».

El pipeline, en 3 scripts (Topohit-Android-/metricas/)

  1. 01_playtest.py descarga las partidas reales de la API (29 partidas) y saca el mínimo, la media y el máximo de cada dato.
  2. 02_simulacion.py crea 400 partidas simuladas con esos rangos y la regla de frustración: si en su primera partida el niño comete muchos errores o pide muchas ayudas, es un 75 % más probable que no vuelva.
  3. 03_analisis.py calcula las métricas (retención, abandono, DAU/MAU…), hace las gráficas, entrena un árbol de decisión y genera informe_metricas.pdf. Resultado: accuracy 0,913 y ROC-AUC 0,865.

🖥️ Escritorio · Métricas

  • El escritorio ejecuta Python del PC (metricas_escritorio.py).
  • Python genera los PNG y el escritorio los enseña.
  • Todas las partidas de todos los niños.
  • Hace falta Python con las librerías: instalar_librerias.bat.
💡 Por qué el modelo de la tablet no usa scikit-learn Chaquopy no tiene scikit-learn para Python 3.11 en 32 bits. Así que el árbol de decisión de la tablet está hecho «a mano» con numpy, siguiendo los mismos pasos, y da exactamente los mismos números que el del escritorio.

9Ponerlo en marcha en la Tab A

  • PC y tablet en la misma wifi.
  • En el PC, mirar la IP: ipconfig → «Dirección IPv4» (por ejemplo 192.168.1.20).
  • Poner esa IP en SharedData.kt: http://192.168.1.20:5110/api/.
  • Arrancar la API (Visual Studio, perfil http). Tiene que salir Now listening on: http://0.0.0.0:5110.
  • Abrir el puerto 5110 en el cortafuegos de Windows (regla de entrada TCP 5110).
  • Comprobar desde el navegador de la tablet: http://192.168.1.20:5110/api/modos/infinito tiene que enseñar datos.
  • Instalar la app en la tablet (con cable USB o con el APK) y entrar con marc / marc1234.
✅ Antes de la primera vez, en cada PC git pull en los 3 repositorios · instalar_dotnet.bat (API) · instalar_librerias.bat (Android y escritorio) · en Android Studio, Gradle JDK 17 o 21.

12Preguntas de repaso

Intenta responderlas antes de leer la respuesta.

1. ¿Por qué la tablet no se conecta directamente a la base de datos?
→ Porque la contraseña de la base de datos solo la debe conocer la API, y así las dos apps comparten los mismos datos y las mismas reglas (roles, candados).
2. ¿Qué hace falta para que la tablet hable con el PC sin cable?
→ Misma wifi, la IP del PC en SharedData.kt, la API escuchando en 0.0.0.0:5110, el puerto abierto en el cortafuegos y el permiso INTERNET.
3. ¿Qué diferencia hay entre localhost, 10.0.2.2 y 192.168.x.x?
→ localhost es el propio PC (escritorio); 10.0.2.2 es el PC visto desde el emulador; 192.168.x.x es el PC visto desde la tablet de verdad.
4. ¿Por qué el manifest tiene usesCleartextTraffic="true"?
→ Porque Android bloquea HTTP sin cifrar y la API de clase va por HTTP, no por HTTPS.
5. ¿Qué viaja por la red al hacer login: la contraseña o su hash?
→ El hash bcrypt. La contraseña nunca sale de la tablet.
6. ¿Qué es el token y dónde se envía?
→ Un pase JWT firmado por la API (dura 8 h). Va en la cabecera Authorization: Bearer … de cada petición.
7. ¿Qué contesta la API si un jugador intenta borrar un usuario?
→ 403 (prohibido): esa llamada solo la permite el rol admin.
8. ¿Qué librería hace las llamadas HTTP en Android, y cuál pasa el JSON a objetos?
→ Retrofit hace las llamadas; Gson pasa el JSON a clases de Kotlin.
9. ¿Por qué las llamadas van dentro de GlobalScope.launch?
→ Para hacerlas en segundo plano; si se hicieran en el hilo de la pantalla, la app se congelaría (Android no lo deja).
10. ¿Hace falta la red mientras el niño juega una partida?
→ No. La partida pasa entera en la tablet; la red solo se usa antes (login, dificultades) y al final (guardar la partida, ranking).
11. ¿Cómo se ejecuta Python en la tablet y por qué se usa la versión 3.11?
→ Con Chaquopy, que mete Python en la app. Se usa la 3.11 porque es la última que Chaquopy tiene para tablets de 32 bits como la Tab A.
12. ¿Qué archivo cambiarías si la tablet no encuentra la API?
→ SharedData.kt (PROJECT_ROOT), y después volverías a instalar la app.
13. ¿Cómo sabe la app qué canción poner y qué pasa al cambiar de temática?
→ Cada temática de Tematicas.kt tiene su campo musica. Al cambiarla, Sonidos.cambiarMusica() para y libera la canción anterior (MediaPlayer) y pone la nueva. No usa la red.
